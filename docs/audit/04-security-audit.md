# 04 Security audit: Story Site Generator (warpdrive-studio)

Date: 04 Nov 2026
Scope: `master` HEAD `71ac7d0` (next deploy candidate). Live is `9953fe6` (`live-08-oct-2026`); every High finding below was checked and is also present in `9953fe6`.
Method: code review of every route in `src/app/api/**`, `src/app/auth/**`, `src/proxy.ts`, `src/lib/**` (auth, keys, publish, renderers, parsing, image generation), `db/schema.sql` and `db/migrations/*`; `npm audit` and `npm audit --omit=dev`; a git-history scan for 15 secret patterns (types only, no values printed); `curl -I` of public live URLs. Nothing was signed up, signed into, fuzzed or deployed, and no Supabase or Vercel API was called.

"Confirmed" means the path was traced in code end to end. "Suspected" means the code path exists but depends on production configuration or on third-party behaviour that was not tested (exploits were not run).

---

## 1. Summary

Every API route calls `requireUser()` and filters by `owner_id`, so there is no plain IDOR through the app's own API: user A cannot read, edit, publish or delete user B's project, keys or documents by changing an id. The AES-256-GCM key storage is done correctly, there are no secrets in git history, and the open-redirect guard holds.

The serious problems are in the layers around the API:

1. **The database is open beyond the API.** The anon key is public (it is in the browser bundle). `db/schema.sql` creates `system_prompts`, `agents` and `skills` without row-level security, and the `projects` policies grant `owner_id is null` rows to everyone, including anonymous callers. Anyone on the internet could rewrite the story-generation system prompt for all users, and read, change or delete every project that has no owner.
2. **Chunk data from the client is trusted.** `POST /api/projects` stores `body.chunks` as is, and `PATCH` keeps client chunk ids. That one gap leads to three exploits: a path traversal that overwrites *other* projects' audio, scene images and logos with the service role (cross-tenant); a full-read SSRF at publish time (the server fetches any `imageUrl` and publishes the bytes); and script injection into published sites.
3. **Auth fails open.** With `AUTH_ENABLED` unset the whole app is an unauthenticated admin console over the production database. Local development runs exactly like that, against the same production Supabase, and `next dev` listens on all network interfaces.
4. **Next.js 16.3.3 has critical advisories** (npm audit), including unauthenticated RCE in the image optimiser with SVGs. `/_next/image` answers on the live app. `sharp` has a librsvg advisory, and the app rasterises user-uploaded SVG logos with it.
5. **Publishing is a shared, unmetered capability on the owner's full-scope Vercel token.** There is no rate limit and no quota. A user can overwrite orphaned sites (and any framework-less, non-Git project on the team). Sign-up looks open with email confirmation off.

Counts: 1 Critical, 6 High, 7 Medium, 9 Low/Info.

Checked and **not** a problem (for the record):
- **IDOR through the API**: every `[id]` route filters by `owner_id` when auth is on (projects GET/PATCH/DELETE, select, publish, generate-audio, case-study audio and video, scene images, bind, audio and video redirects). Settings keys always use `user.id`. Documents are read only from the caller's own `<user_id>/` folder. Logo paths are tied to the caller's prefix.
- **Crypto** (`src/lib/userKeys.ts`): AES-256-GCM, a random 96-bit IV for each value, a 128-bit tag, AAD `userId:provider` (blocks moving a ciphertext to another row), a key-length check, and errors that do not reveal internals. The full key is never returned or logged; only the last 4 characters are kept as a hint. Gap: no key id in the `v1` format, so rotating `KEY_ENCRYPTION_SECRET` needs a re-encryption script.
- **Open redirect**: `safeNextPath()` blocks `//`, `/\`, absolute URLs and control characters. The callback and login use it.
- **Proxy matcher**: excluding `/api` is safe because routes call `requireUser()` themselves. Paths with a file extension skip the proxy, but pages are client components that load data through the authenticated API.
- **`NEXT_PUBLIC_*`**: only the Supabase URL and anon key, as intended. The service-role key is not reachable from client code.
- **SVG sanitiser** (`sanitizeSvg.ts`): a solid allow-list parser that fails closed. The problem is that its use can be skipped (SEC-07), not the sanitiser itself.
- **Private `documents` bucket**: there are no storage policies, so anon cannot list or read it.
- **LLM output in published HTML**: titles, narration words, lists, case-study fields and Voyage JSON are all escaped. Case-study section keys come from a fixed list. Prompt injection from a document can change story *wording* but was not found to inject markup.

## 3. Must fix before the next deploy

In order. Items 1 and 2 are database-only and also protect the current live app, so do them first and independently of the deploy.

1. **SEC-01**: enable RLS on `system_prompts`, `agents`, `skills`; run Supabase Security Advisor; check that no unexpected rows exist in `system_prompts` (look for rows not created by the team).
2. **SEC-02**: replace the `projects` policies; assign or lock the ownerless rows.
3. **SEC-06 and SEC-07 (dependency part)**: upgrade `next` to 16.4.5 or later and `sharp` to 0.35.5 or later (`npm audit fix`, plus a `next` bump), or set `images.unoptimized` as a stopgap.
4. **SEC-03, SEC-04, SEC-08, SEC-21**: server-side chunk validation (id allow-list, no client `imageUrl`/`audioUrl`) and a safe storage-path helper; escape `audioSrc`; publish bundles storage objects only.
5. **SEC-05**: fail closed when `AUTH_ENABLED` is missing in production; bind dev to 127.0.0.1; stop pointing local dev at the production database with the service-role key.
6. **SEC-10 and SEC-13**: close public sign-up (or allow-list) and turn email confirmation on; move story-site publishing to a dedicated Vercel account and token; rotate (section 4).
7. **SEC-07 (logo flow)**: only accept server-verified logo paths.

Next sprint: SEC-09, SEC-11, SEC-12, SEC-14, then the Low items.

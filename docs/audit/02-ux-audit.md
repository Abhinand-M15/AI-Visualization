# UX audit: Story Site Generator (warpdrive-studio)

Audit date: 04 Nov 2026. Code audited: `master` HEAD `71ac7d0` (the next deploy). Live is `9953fe6`; between the two, the only user-facing UI changes are in `SceneImagesPanel.tsx` (case-study sections listed in Showcase mode) and the preview page (section images). Every finding below also applies to the live app unless it says otherwise.

Viewpoint: a first-time internal user who has never seen the app, has a Gemini key or can get one, and wants to turn one document into a published, narrated story site.

## Summary

The bones are good: sign-up drops straight into a clear "add your Gemini key" step, the library page has search, status badges and a copyable live URL, the publish dialog has a live address check, focus trap, progress and a clear "Your story is live" result, and audio/image generation stream real progress and save as they go.

The weak spots are all about **work that can be lost or stuck** and **a project page that asks too much at once**:

1. On `/new`, a failed "Regenerate" or "Save project" throws away the whole generated draft and every edit (the only button is "Start over"). The draft also lives only in memory, so a refresh or tab close loses it, with no warning.
2. Editing chapters while "Generate audio" is running can be silently overwritten when the audio job finishes.
3. A publish that hits Vercel's 300 s limit leaves the project marked "Publishing" forever; the Publish/Republish buttons stay disabled and there is no way to recover in the UI.
4. Showcase says it needs no avatar, but Preview and Publish stay blocked until you pick one.
5. Errors from Gemini, Vercel and the server reach users as raw text (JSON, "Unexpected token…", env-var names), and an invalid Gemini key is not routed back to Settings.

Fixing the first three alone removes every "I lost my work" and "I'm stuck" path found.

## Quick wins (S effort, highest value first)
